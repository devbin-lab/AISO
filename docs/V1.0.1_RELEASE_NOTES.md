# Aiso v1.0.1

2026-08-21

## 이번 릴리스

v1.0.0 이후 27개 변경을 담았습니다. 큰 줄기는 세 가지입니다.

- **에이전트가 조용히 틀리지 않게** — 실패한 웹 검색·차단된 페이지를 성공으로 세지 않고, 막힌 1차 출처 대신 다른 출처를 찾아갑니다.
- **멈춰도 이어갈 수 있게** — 왜 멈췄는지 사실대로 알리고, 원하면 스스로 이어서 진행합니다.
- **경계를 좁게** — 렌더러 CSP, 셸 명령의 외부 실행기 차단, 검증 코드의 Job Object 봉쇄.

홈 화면이 대시보드가 되었고, My DB 휴지통에 완전 삭제가 생겼습니다.

## 새 기능

- **홈 대시보드** — 연결 상태, 오늘 할 일, 이번 주 토큰 사용량, My DB 일일 변경 보고서를 한 화면에 모았습니다. 바깥은 고정하고 넘치는 내용은 카드 안에서 스크롤합니다. 좁은 창에서는 한 화면 제약을 풀어 끝까지 읽을 수 있습니다.
- **작업 자동 이어가기** (설정 → LLM, 기본 꺼짐) — 안전 한도로 멈춘 작업을 사용자가 매번 '계속해줘'라고 치지 않아도 이어서 진행합니다. 한 요청당 3회까지만 이어가며, 정지를 누른 뒤에는 이어가지 않습니다. 토큰을 더 쓰는 기능이라 기본값은 꺼짐입니다.
- **My DB 휴지통 완전 삭제** — 되돌릴 수 없는 유일한 동작이라 휴지통을 거친 항목만 대상이며 확인 절차를 거칩니다. 보관 파일과 버전 스냅숏은 사라지지만 이력 기록은 남고, My DB 밖에 있는 사용자의 원본 파일에는 손대지 않습니다. 완전 삭제한 항목은 이전 시점의 체크포인트를 복원해도 되살아나지 않습니다. 이 기능은 사용자만 쓸 수 있으며, 에이전트에게는 어떤 삭제 경로도 열려 있지 않습니다.
- **2차 출처 탐색** — 1차 출처가 안티봇 페이지로 막히면 그 사실을 알리고 다른 출처를 대신 엽니다. 막힌 시도는 읽기 예산을 쓰지 않으므로, 답이 검색 스니펫이나 모델 기억으로 떨어지지 않습니다.
- **현재 시각 제공** — '최신·오늘 기준' 질문에 요청 시점의 날짜·요일·시각·시간대를 모델에 함께 줍니다. 앱을 며칠 켜 두어도 기준 날짜가 어긋나지 않습니다.

## 고친 문제

### 웹 조사

- 검색이 헤드리스 브라우저를 띄우지 않고 직접 요청으로 처리합니다. 브라우저 기동 실패로 조사가 멈추던 간헐 오류(특히 gemma 계열에서 잦았습니다)가 사라졌고, 검색 한 번이 약 1초로 끝납니다. 직접 요청이 차단되면 브라우저 경로로 자동 전환하며, 둘 다 실패하면 각각의 사유를 함께 보고합니다.
- 검색 결과가 0건이어도 "성공"으로 넘기던 문제를 고쳤습니다. 파싱이 깨져도 조용히 지나가는 대신 실패를 실패로 알립니다.
- 안티봇 대기 페이지를 "원문을 읽었다"로 세지 않습니다. 본문을 실제로 확보했는지 길이로 판정합니다.

### 에이전트 실행

- 멈춘 이유를 사실대로 알립니다. 출력이 잘렸을 때 "컨텍스트 길이를 늘리라"고 안내하던 것이 잘못이었습니다 — 실제 원인은 한 턴 출력 상한이라 컨텍스트를 늘려도 달라지지 않습니다. 여섯 가지 중단 안내를 각각의 실제 원인과 처방으로 다시 썼습니다.
- 취소·재시도·크래시에서 파괴적 도구가 중복 실행되지 않도록 하는 '정확히 한 번' 보장을 기본 경로(로컬 Ollama)에도 적용했습니다. 이전에는 NVIDIA 경로에만 있었습니다.
- 안전 한도로 멈춘 실행이 '실제로 한 일'과 '그 결과가 무엇이었는지'를 다음 실행으로 넘깁니다. '계속해줘'가 백지에서 시작하지 않습니다.
- 승인 대기가 시간 초과되면 **사용자가 거부한 것으로 기록**되던 문제를 고쳤습니다. 이제 승인·거부·시간 초과를 구분해 기록합니다(실행 원장 스키마는 자동 이관되며 기존 기록은 보존됩니다). 승인되지 않으면 실행하지 않는다는 판단 자체는 그대로입니다.
- 채널 보고 예약이 승인을 받은 뒤에야 검증되던 순서를 바로잡았습니다.
- 파일 도구를 워커 스레드로 옮겨, 도구가 도는 동안 스트리밍·취소가 멈추던 현상을 없앴습니다.
- 재색인·스키마·컨텍스트·승인·정체 감지의 하네스 정확성 결함을 수정했습니다.

### 저장소 관리

- My DB 그래프 체크포인트와 파일 리비전이 무한히 쌓이던 것을 보존 정책으로 제한했습니다.
- 참조되지 않는 대화 첨부를 정리합니다. 이전에는 쌓이기만 했습니다.
- 설치본이 빌드 출력 폴더의 임시 파일까지 담던 문제를 고쳤습니다. 패키징 대상을 실제 빌드 산출물로만 좁혔습니다.

## 보안

- **렌더러 CSP 도입** — 렌더러에 CSP가 전혀 없던 상태였습니다. 세션 헤더 방식으로 사이드카 포트만 정확히 엽니다.
- **셸 명령의 외부 실행기 차단** — `run_command`가 `start`, `mshta` 같은 외부 앱·URL 핸들러를 실행할 수 없습니다. 자동 모드는 승인을 생략하므로 한 줄로 기본 브라우저를 통해 데이터가 나갈 수 있었습니다.
- **검증 코드의 Job Object 봉쇄** — `run_code`가 실행하는 코드는 자식 프로세스를 만들 수 없고, 메모리 상한이 걸리며, 검증이 끝나면 손자 프로세스까지 함께 종료됩니다. 네트워크와 작업 폴더 밖 파일 접근은 **막지 않습니다** — 이것은 봉쇄이지 격리가 아닙니다. 자세한 범위는 README의 표를 참고하세요.

## 내부 정비

- **mypy를 게이트로** — 설정·실행 경로·검사 명령이 없던 상태에서 `npm run typecheck:python`으로 0건 기준선을 세웠습니다.
- **죽은 코드 1,571줄 제거** — 폐기된 knowledge_graph 계층, v1.0.0 리팩터 잔재, 전수조사가 찾은 죽은 CSS·함수, 대체된 NVIDIA 승인 경로.

## 호환성과 주의사항

- 기존 작업 폴더, 대화, 캘린더, My DB 데이터는 그대로 유지됩니다.
- 새 설정 **작업 자동 이어가기**는 기본 꺼짐입니다. 켜면 한 요청이 최대 4회(최초 1회 + 자동 3회) 실행될 수 있어 토큰을 더 씁니다.
- **My DB 완전 삭제는 되돌릴 수 없습니다.** 완전 삭제 후에는 그 이전 시점의 그래프 체크포인트를 복원해도 해당 항목이 돌아오지 않습니다.
- My DB 보존 정책이 적용되면서 아주 오래된 그래프 체크포인트와 파일 리비전은 정리됩니다.
- `run_code`의 봉쇄는 네트워크를 막지 않습니다. 최종 안전장치는 여전히 권한 모드입니다.
- 자동 권한 모드는 켜진 도구를 승인 없이 실행합니다. 신뢰할 수 있는 모델과 작업 범위에서만 사용하세요.
