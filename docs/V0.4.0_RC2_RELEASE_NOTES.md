# Aiso v0.4.0-rc.2 릴리스 노트

| 항목 | 내용 |
|---|---|
| 버전 | `0.4.0-rc.2` |
| 작성일 | 2026-08-02 |
| 기준 안정판 | `v0.3.1` |
| 이전 후보판 | `v0.4.0-rc.1` |
| 상태 | Release Candidate · 실환경 결함 수정 후 재검증 |

v0.4.0-rc.2는 첫 NVIDIA Build 실환경 점검에서 확인된 자격 증명 재실행 오류와 Agent UI 결함을 수정합니다. v0.4.0-rc.1의 NVIDIA 공급자·기능 검사·전송 승인·데이터 경계는 그대로 유지합니다. 전체 기능과 설정 방법은 [v0.4.0-rc.1 릴리스 노트](V0.4.0_RC1_RELEASE_NOTES.md)를 함께 참고하십시오.

## 수정 사항

### NVIDIA API 키 재실행 안정성

- 원인: 개발 모드에서 Chromium `sessionData`까지 프로세스 PID별 임시 폴더로 분리해, Electron async `safeStorage`의 `Local State` 암호 키도 매 실행 바뀌었습니다. 영구 저장된 API 키 파일은 남았지만 다음 실행에서 해독할 수 없었습니다.
- 수정: 개발 `sessionData`는 `chromium-session-dev`, 설치본은 `chromium-session`으로 각각 고정했습니다. Windows 접근 거부를 일으키던 HTTP/GPU 캐시만 개발 PID별 폴더로 분리합니다.
- 격리: 설치본과 개발본은 서로 다른 Chromium 프로필과 NVIDIA 자격 증명 파일을 사용합니다. 한쪽 환경의 암호 키를 다른 환경에서 잘못 재사용하지 않습니다.
- 복구: 저장 파일의 존재만 확인하지 않고 Main 프로세스에서 실제 복호와 배포 대상 일치를 확인합니다. 사용할 수 없는 키는 외부로 보내지 않고 `설정 → LLM`에서 다시 입력하도록 안내합니다.

v0.4.0-rc.1 개발본에서 이미 저장한 키는 새 개발 자격 증명 파일로 자동 복사하지 않습니다. rc.2를 처음 실행한 뒤 같은 API 키를 한 번 다시 저장해야 합니다.

### Agent 모델 표시와 승인 UX

- Agent 모델 선택 표시가 Ollama의 `settings.model`만 보던 문제를 수정했습니다. NVIDIA가 활성 공급자이면 설정에서 선택한 `nvidiaModel`을 표시하고 해당 필드만 갱신합니다.
- 실제 Agent 요청은 기존에도 공급자별 모델 스냅샷을 사용했으며, 이번 수정은 화면 표시와 편집 대상을 동일한 계약으로 맞춥니다.
- 도구 승인 API가 HTTP 200과 `{ ok: false }`를 반환하거나 비정상 응답을 보낼 때 성공으로 오인하지 않습니다.
- 승인 응답을 기다리는 동안 승인 바를 유지하고 버튼을 잠급니다. 실패하면 오류를 승인 바 안에 표시하고 승인·거부 버튼을 다시 활성화합니다.
- 늦게 도착한 승인 응답이 이미 완료된 도구 결과를 덮어쓰지 않도록 상태 전이를 제한했습니다.
- 백엔드가 응답하지 않는 승인 요청은 10초 후 중단하고 같은 승인 바에서 다시 시도할 수 있게 했습니다.

## 재검증 절차

1. 설치본 Aiso를 트레이 메뉴에서 완전히 종료합니다.
2. 개발 서버도 종료한 뒤 `npm run dev`를 다시 실행합니다.
3. `설정 → LLM → NVIDIA`에서 API 키를 한 번 다시 저장합니다.
4. 모델 목록을 새로고침하고 사용할 모델을 선택한 뒤 기능 검사를 실행합니다.
5. 채팅에서 짧은 일반 대화를 전송하고 선택 모델의 응답을 확인합니다.
6. Agent에서 NVIDIA 전송 범위를 승인한 뒤, 화면 하단 모델명이 설정의 NVIDIA 모델과 같은지 확인합니다.
7. 승인이 필요한 읽기 또는 작업을 요청해 승인 UI와 실행 결과를 확인합니다.
8. Aiso를 완전히 종료하고 다시 실행한 뒤 5~7단계를 반복해 키가 유지되는지 확인합니다.

이 RC는 안정판이 아닙니다. 실제 NVIDIA Build 채팅과 Agent의 재실행 검증이 완료되기 전에는 v0.4.0 안정판으로 확정하지 않습니다.
