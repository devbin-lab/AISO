# Aiso v0.4.0-rc.4 릴리스 노트

| 항목 | 내용 |
|---|---|
| 버전 | `0.4.0-rc.4` |
| 작성일 | 2026-08-03 |
| 기준 안정판 | `v0.3.1` |
| 이전 후보판 | `v0.4.0-rc.3` |
| 상태 | Release Candidate · 공급자별 도구 정책 및 선택적 프로그래밍 검증 |

v0.4.0-rc.4는 Aiso의 역할 제한을 고정된 기능 삭제가 아니라 사용자가 선택하는 도구 정책으로 전환합니다. 소형 로컬 모델에서는 프로그래밍 기능을 끈 안전한 기본값을 유지하고, 사용자가 성능을 확인한 NVIDIA 모델에서는 필요한 코드 도구만 켤 수 있습니다.

## 공급자별 도구 정책

- `설정 → 도구`에서 로컬 모델과 NVIDIA의 허용 목록을 각각 저장합니다.
- 프로젝트 프로그래밍 스위치는 코드 작성·편집과 코드·명령·웹 실행 6개를 한 번에 제어합니다.
- 묶음 상태를 바꾼 뒤에도 각 도구를 개별적으로 다시 조정할 수 있습니다.
- 새 설치와 v3·v4 설정 마이그레이션은 프로그래밍 도구가 꺼진 상태로 시작합니다.
- NVIDIA 데스크톱 Agent가 아직 지원하지 않는 웹 조사·사용자 스킬·Discord 항목은 목록에 표시하되 스위치를 비활성화합니다.

도구 ON/OFF와 수동·읽기·자동 권한은 서로 다른 축입니다. OFF 도구는 어떤 권한 모드에서도 모델에 노출하거나 실행하지 않습니다. ON 도구는 기존 승인 정책을 그대로 따르며, 코드·명령·브라우저 실행과 삭제·외부 발신은 자동 모드에서도 승인을 유지합니다.

## 프로젝트 프로그래밍

다음 도구를 추가하거나 선택적 프로그래밍 묶음으로 편성했습니다.

- `write_code_file`: UTF-8 프로젝트 파일 생성·덮어쓰기
- `edit_code_file`: 유일한 문자열 일치 한 곳 편집
- `multi_edit_code_file`: 여러 편집을 모두 검증한 뒤 한 번에 적용
- `run_code`: Python·C·C++·C# 실행 및 기본 검증
- `run_command`: 프로젝트 명령·테스트 실행
- `run_web`: HTML 결과 실행과 브라우저 검증

Markdown 문서 도구는 계속 `.md` 전용입니다. 코드 도구는 작업 폴더 안에서만 동작하고, `.git`·의존성·가상환경 폴더, `.env`·인증서·개인 키, 바이너리와 비 UTF-8 파일을 거부합니다. Windows CRLF 파일도 줄바꿈을 중복 변환하지 않고 UTF-8 바이트를 보존합니다.

## 실행 경계

- 실행 시작 시 저장된 도구 허용 목록을 불변 스냅샷으로 고정합니다.
- OFF 도구는 LLM 함수 스키마에서 제외합니다.
- 모델이 OFF 또는 존재하지 않는 도구를 강제로 호출하면 실행 전에 거부합니다.
- 허용 도구와 비허용 도구를 한 응답에 섞으면 허용 도구까지 포함해 전체 묶음을 실행하지 않습니다.
- `run_skill`이 꺼져 있으면 등록된 동적 스킬 이름도 모델에 노출하지 않습니다.
- 시스템 지시는 이번 실행에 실제로 노출된 도구 목록과 프로그래밍 상태를 명시합니다.

NVIDIA 실행에서는 Renderer 요청값을 신뢰하지 않습니다. Main 프로세스가 저장 설정에서 정확한 `allowedTools`를 만들고 승인 fingerprint에 포함하며, Python 사이드카는 일회성 grant의 범위를 다시 검증합니다. NVIDIA 도구 정책이 바뀌면 이전 Agent 승인은 폐기됩니다.

## 자격 증명 보호

코드·명령·웹 실행 자식 프로세스에는 Aiso 인증 토큰뿐 아니라 알려진 클라우드 API 키와 `_API_KEY`, `_ACCESS_TOKEN`, `_CLIENT_SECRET`, `_PASSWORD` 같은 비밀 환경변수를 전달하지 않습니다. 이 보호는 자식 프로세스 출력이 Agent 대화나 NVIDIA 모델로 되돌아오는 경로에도 적용됩니다.

## 실환경 확인 절차

1. `npm run dev`로 개발본을 실행하고 `설정 → 도구`를 엽니다.
2. `로컬 모델`에서 프로젝트 프로그래밍이 기본적으로 꺼져 있는지 확인합니다.
3. `NVIDIA`로 전환해 프로젝트 프로그래밍을 켠 뒤 설정을 저장합니다.
4. Agent에서 신뢰할 수 있는 작은 테스트 작업 폴더를 선택합니다.
5. NVIDIA 모델에 간단한 소스 파일 생성·수정과 테스트 실행을 요청합니다.
6. 코드 작성 결과와 코드·명령 실행 승인 UI가 구분되어 나타나는지 확인합니다.
7. 프로그래밍을 다시 끄고 같은 요청을 보냈을 때 코드 도구가 호출·실행되지 않는지 확인합니다.
8. 로컬 모델 정책이 NVIDIA 정책과 별도로 유지되는지 확인합니다.

이 RC는 안정판이 아닙니다. 실제 사용 모델별 코드 정확도와 승인 흐름을 확인한 뒤 v0.4.0 안정판 포함 여부를 결정합니다.
