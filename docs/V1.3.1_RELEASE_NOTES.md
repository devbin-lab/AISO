# Aiso v1.3.1

2026-08-23

## 이번 릴리스

**설치한 적 없는 ComfyUI를 '정상'으로 표시하던 문제**를 고쳤습니다. 처음 세팅하는 컴퓨터에서 가장 나쁜 종류의 거짓말이라 우선 처리했습니다. 진단 센터의 시나리오 기반 QA 평가팩은 제거했습니다.

## 수정

### ComfyUI 연결 판정

- **ComfyUI가 없는데 '정상'으로 뜨던 문제** — 앱을 처음 받은 컴퓨터에서 ComfyUI를 설치조차 하지 않았는데도, 새 채팅의 연결 상태 카드와 진단 센터가 모두 `정상`으로 표시했습니다. 준비가 됐다고 믿고 이미지 생성을 시도하게 되는 상태였습니다.

  원인은 판정이 `response.ok`만 본 것입니다. 그건 **사이드카가 답했다**는 뜻일 뿐입니다. 사이드카의 `/comfy/health`는 ComfyUI가 죽어 있어도 HTTP 200에 `{ online: false }`를 담아 돌려주므로(`python/comfy_client.py`의 `_offline`), 이 조건은 사실상 늘 참이었습니다.

  이제 응답 **본문**의 `online`을 읽습니다. 실제로 살아 있을 때만 `정상`이고, 아니면 `확인 필요`와 함께 사이드카가 준 사유("ComfyUI에 연결할 수 없습니다.")를 그대로 보여 줍니다. 본문이 JSON이 아니거나 사이드카 자체가 오류를 내는 경우에도 `정상`으로 넘기지 않습니다.

  홈 카드와 진단 센터는 같은 판정 함수를 쓰므로 두 화면이 함께 고쳐집니다.

## 제거

- **시나리오 기반 QA 평가팩** — 진단 센터에서 실행하던 회귀 시나리오 묶음을 없앴습니다. 화면, 상태, 스타일, 사이드카 엔드포인트(`POST /qa/scenarios/run`), 시나리오 정의와 그 테스트까지 함께 지웠습니다. 진단 센터의 나머지 점검(백엔드·모델·ComfyUI·Discord·작업 환경)은 그대로입니다.

## 호환성과 주의사항

- 판정 로직만 바뀝니다. ComfyUI 설정값, 모델 프로필, 워크플로는 그대로입니다.
- 이미 ComfyUI를 실행 중이라면 표시는 이전과 같습니다. 달라지는 것은 **꺼져 있을 때**입니다.
- 기존 작업 폴더, 대화, 캘린더, My DB 데이터는 그대로 유지됩니다. 저장 형식 변경은 없습니다.
- v1.3.0에서 그대로 업데이트할 수 있습니다.

## 알려진 문제

- v1.3.0의 그래프 관련 알려진 문제는 그대로입니다 — 코어 하나에 자기 파일이 많으면서 동시에 코어 자식도 많으면 그 코어의 파일끼리 겹칠 수 있습니다. [v1.3.0 릴리스 노트](V1.3.0_RELEASE_NOTES.md)를 참고하세요.

## 검증

- 이 컴퓨터에서 ComfyUI가 **실제로 꺼져 있음**을 먼저 확인했습니다(8188 포트 닫힘, `/system_stats` 무응답). 즉 이전에 '정상'으로 찍히던 것이 버그임을 실측으로 확정했습니다.
- 판정 계약을 고정하는 회귀 테스트 7개를 추가하고, 옛 코드로 되돌리면 그중 4개가 실제로 실패하는지 확인했습니다.
- 기존 홈 화면 테스트가 이 버그에 기대고 있었음이 드러나 함께 바로잡았습니다.

- Python 테스트 1,607개 통과
