# Aiso v1.3.0

2026-08-23

## 이번 릴리스

My DB 그래프가 **선이 엉키지 않는 방사형 배치**로 바뀌었습니다. 화면을 좁혔을 때 어긋나던 설정·목록 배치도 함께 고쳤습니다.

- **선이 서로 가로지르지 않습니다** — 간선 교차 9건 → 0건, 선이 남의 노드를 뚫는 것 9건 → 0건.
- **자식이 부모를 빙 두릅니다** — 한쪽으로 몰린 부채꼴이 사라졌습니다.
- **군집이 하나의 둥근 뭉치로 모입니다** — 흩어져 있던 덩어리를 원형으로 채웁니다.
- **노드가 서로 겹치지 않습니다** — 보이는 원보다 큰 충돌 원을 둘렀습니다.

## 새 기능 · 개선

### My DB 그래프

- **선이 엉키지 않습니다.** 이 그래프는 모든 연결이 `contains`인 트리이므로, 하위 트리를 서로 겹치지 않는 영역에 놓으면 교차가 **구성상** 0이 됩니다. 배치를 그렇게 다시 짰습니다. 줄인 값이 아니라 0입니다.

  실측(코어 41 · 파일 116 · 간선 152):

  ```
             전     후
  간선 교차   9  →  0
  노드 관통   9  →  0
  노드 겹침   1  →  0
  ```

- **자식이 부모를 빙 두릅니다.** 예전에는 노드가 **부모에게 물려받은 부채꼴 안에서만** 자식을 펼쳤습니다. 그래야 형제 영역이 안 겹치지만, 갈림길마다 각이 반씩 잘려 깊은 노드는 구조적으로 부채꼴이 됐습니다. 하위 트리를 부채꼴이 아니라 **원뿔**로 잡아 그 제약을 풀었습니다 — 부모에서 본 각 구간만 서로 배타적이면 되므로 자식이 부모 둘레 어디에나 앉을 수 있고, 중심에서 뻗는 선은 각도가 다른 원뿔을 지날 수 없어 교차는 여전히 0입니다.

  ```
  2학기              177° → 315°
  1학기              193° → 300°
  게임데이터의설계     157° → 240°
  방사 균등도        0.874 → 0.982
  ```

  같은 이유로 예전에는 갈래 구조가 유리한 가지(중간에 외동이 끼거나 뿌리인 가지)만 시원하게 퍼져 보였습니다. 이제 구조와 무관하게 고르게 퍼집니다.

  남은 숫자는 배치의 흠이 아니라 **기하학의 천장**입니다. 자식이 n명이면 중심 사이 틈의 합이 360°이므로 폭은 360 − 360/n을 넘을 수 없습니다(n=3이면 240°). 19개 부모 전부가 각자의 천장에 닿아 있습니다.

- **군집이 하나의 둥근 뭉치로 모입니다.** 서로 연결되지 않은 덩어리들이 흩어져 빈 자리만 넓었습니다. 이제 큰 덩어리를 가운데 놓고 나머지를 원점에 가장 가까운 빈자리에 붙여, 전체가 원에 가깝게 찹니다. 배치 상자 비율 0.73 → **1.06**, 감싸는 반지름 2,165px → **1,093px**.

  덩어리는 통째로 평행이동만 합니다. 강체 이동이라 덩어리 안의 기하는 그대로이고, 덩어리끼리는 간선이 없으므로 모아도 새 교차가 생기지 않습니다.

- **노드가 서로 겹치지 않습니다.** 겹침을 막던 것이 반발력뿐이었는데, 그 힘은 거리가 멀수록 약해지는 데다 배치가 식으면서 함께 사라집니다. 그래서 겹친 채 멈춘 화면이 남았습니다. 이제 힘이 아니라 **위치 제약**으로 매 프레임 떼어 놓습니다. 그리는 원보다 큰 원을 쓰므로 라벨이 붙는 노드끼리도 붙어 보이지 않습니다.

- **전체 보기가 배치 크기에 맞춰집니다.** 예전에는 배율이 고정이라 라이브러리가 커지면 가장자리 군집이 화면 밖으로 잘렸습니다. 이제 배치가 차지하는 자리를 재서 전체가 들어오도록 맞춥니다.

### 화면

- **설정 탭을 옮길 때 메뉴가 위로 튀던 문제** — 창을 좁히면 `LLM`·`도구` 탭에서만 왼쪽 설정 메뉴가 위로 올라갔습니다.

  세로 스크롤바(8px)가 원인이었습니다. 배치를 정하는 기준 폭에 스크롤바가 포함되어, 내용이 길어 스크롤이 생기는 탭만 폭이 8px 좁아지고 그 차이가 배치 경계를 넘겼습니다. 실측으로 창 1,080px에서 다른 탭은 824px인데 `LLM`·`도구`만 816px이었습니다. 이제 스크롤바 자리를 항상 잡아 두므로 아홉 개 탭이 모두 같은 폭·같은 배치입니다.

- **목록 화면의 형식 필터가 가로 스크롤바에 가리던 문제** — 필터 줄 높이가 29px로 고정인데 가로 스크롤바가 10px를 차지해, 26px짜리 버튼 아래가 7px 잘렸습니다. 이제 내용 높이로 두고 스크롤바 자리를 따로 확보합니다.

## 호환성과 주의사항

- 그래프 **배치만** 바뀝니다. My DB의 코어·파일·관계·이력 데이터는 그대로입니다.
- 배치가 예전보다 넓게 자리를 씁니다. 노드를 실제 크기대로 재서 겹치지 않게 놓기 때문이며, 전체 보기가 자동으로 맞춰 주므로 처음 열 때는 더 축소된 상태로 보입니다.
- 교차 0은 **모든 연결이 `contains`인 트리**일 때 구성상 보장됩니다. 사용자가 직접 만든 그 밖의 연결선은 어떤 방사형 배치로도 평면화되지 않습니다(일반 그래프는 평면이 아닐 수 있습니다).
- 기존 작업 폴더, 대화, 캘린더, My DB 데이터는 그대로 유지됩니다. 저장 형식 변경은 없습니다.
- v1.2.0에서 그대로 업데이트할 수 있습니다.

## 알려진 문제

- 코어 하나에 **자기 파일이 많으면서 동시에 코어 자식도 많으면**(예: 파일 30개 + 자식 20개) 그 코어의 파일끼리 겹칠 수 있습니다. 구조선이 사방을 막아 파일을 고르게 두를 자리가 없을 때 대체 배치로 넘어가는데, 거기서 좁은 호에 파일이 눌립니다. 실측으로 겹침 10건(최대 5.5px)이며 교차·관통은 없습니다.

  이 릴리스가 만든 문제가 아니라 이전부터 있던 것이고(같은 조건에서 이전 배치도 동일하게 10건), 지금 규모의 라이브러리에서는 나타나지 않습니다. 다음 릴리스에서 다룹니다.

## 검증

- 배치 품질을 **실제 라이브러리로 수치화**했습니다. 눈으로만 보면 한 곳을 펴다 다른 곳이 엉키는 것을 놓치므로, 교차·관통·겹침·퍼짐을 재는 도구를 만들어 기준으로 삼았습니다.
- 회귀 테스트가 실효성이 있는지 확인했습니다 — 옛 배치로 되돌리면 다섯 개가 실패합니다.
- 생성 형상 27종(무작위 숲 최대 605노드, 40단 외줄기, 자식 70개 별, 한쪽으로 치우친 트리)에서 겹침·교차·관통 0, 좌표에 NaN 없음, 같은 입력이면 같은 출력임을 확인했습니다.
- 물리가 배치를 흐트러뜨리는 정도가 3%(1,887×1,817 → 1,944×1,890)임을 실행 중인 앱에서 실측했습니다.
- 설정 탭 아홉 개가 세 가지 창 폭에서 모두 같은 배치임을 실측했습니다.
- TypeScript 검사 통과 (main / renderer)
- mypy 통과 — 42개 파일 0건
- Python 테스트 1,608개 통과
- Renderer 테스트 220개 통과 (그래프 60개 — 배치 불변식 27개 포함)
- Node 게이트 177개 통과 / 실패 0
