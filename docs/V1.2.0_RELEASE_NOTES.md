# Aiso v1.2.0

2026-08-22

## 이번 릴리스

휴지통을 한 번에 비우는 방법과, 오래된 항목을 알아서 정리하는 기한을 더했습니다.

- **휴지통 비우기** — 하나씩 지우지 않고 휴지통을 통째로 비웁니다.
- **기한이 지나면 자동으로** — 버린 지 정해 둔 기한이 지난 항목을 알아서 완전 삭제합니다. 기한은 설정에서 정하며, **기본값은 사용 안 함**입니다.

## 새 기능

- **휴지통 비우기** — 휴지통 화면 왼쪽 아래에 버튼이 생겼습니다. 휴지통이 비어 있으면 눌리지 않습니다.

  완전 삭제는 My DB에서 유일하게 되돌릴 수 없는 동작이라, 단건 삭제와 같은 확인 절차를 거칩니다. 다만 이름을 하나씩 확인할 수 없으므로 **무엇이 몇 개** 사라지는지를 말합니다.

  ```
  휴지통의 코어 3개 · 파일 5개를 완전히 삭제합니다.
  보관된 파일과 모든 버전 기록이 함께 사라지며 되돌릴 수 없습니다.
  ```

  코어와 파일을 나눠 세는 이유는 버전 기록이 파일에만 딸려 있기 때문입니다. 휴지통에 코어만 있으면 버전 기록 문장은 아예 나오지 않습니다.

  내부적으로는 단건 완전 삭제 경로를 그대로 반복합니다. 완전 삭제는 행을 지우는 것만이 아니라 보관 파일과 리비전 폴더 제거, 파일 감시 핸들 정리, 되살아남 방지 기록, 이력 남기기가 한 묶음입니다. 일괄 삭제를 따로 구현하면 단건 삭제와 조용히 어긋납니다.

  한 건이 실패해도 나머지는 계속 지웁니다. 중간에 멈추면 사용자는 무엇이 남았는지 알 수 없고, 다시 눌러도 같은 항목에서 다시 멈춥니다. 실패가 있었으면 몇 개를 지웠고 몇 개가 남았는지 함께 알립니다.

- **휴지통 자동 비우기 기한** (설정 → DB) — 휴지통에 버린 지 이 기한이 지난 항목을 완전히 삭제합니다. 사용 안 함 / 7 · 14 · 30 · 60 · 90 · 180 · 365일 중에서 고릅니다.

  **기본값은 사용 안 함입니다.** 되돌릴 수 없는 동작이 사용자가 켜지도 않았는데 도는 일은 없어야 합니다. 같은 이유로 기한 `0`은 '즉시 삭제'가 아니라 '자동 비우기 안 함'으로 읽습니다 — 이 판정은 테스트로 고정해 두었습니다.

  검사 시점은 앱 시작, 전날 보고 확인 주기, 자정 직후입니다. 이미 있던 보고서 스케줄러에 얹었으므로 타이머가 늘지 않습니다. 기한을 줄이면 다음 주기를 기다리지 않고 그 자리에서 한 번 더 돕니다. 실제로 지운 항목이 있을 때만 열려 있는 창에 알려, 휴지통을 열어 둔 채였다면 화면이 그 자리에서 갱신됩니다.

- **휴지통이 언제 비워지는지 화면이 말합니다** — 항목마다 `7일 남음`처럼 남은 기한을 붙이고, 기한이 지난 항목은 `곧 삭제`로 적습니다. 다음 검사 주기에 사라지므로 `0일 남음`처럼 정확한 척하지 않습니다.

  자동 비우기가 꺼져 있으면 카운트다운 대신 버린 날짜(`8/22 버림`)만 적습니다. 켜지지도 않은 기능의 남은 날짜를 보여 주면 곧 지워질 것처럼 읽힙니다. 화면 위쪽에는 현재 정책을 한 줄로 밝힙니다.

## 호환성과 주의사항

- **자동 비우기는 꺼진 채로 업데이트됩니다.** 켜기 전까지 휴지통 항목은 그대로 남습니다.
- **기한을 켜면 이미 기한이 지난 항목은 곧바로 삭제됩니다.** 예를 들어 30일 전에 버린 항목이 있는 상태에서 기한을 7일로 정하면 다음 검사(설정 변경 직후)에 사라집니다. 되돌릴 수 없으므로, 남기고 싶은 항목은 먼저 복원해 두세요.
- 자동 비우기도 사람이 누르는 완전 삭제와 같은 범위입니다 — 휴지통 안의 항목만 지우고, 살아 있는 코어·파일은 건드리지 않습니다. My DB 밖에 있는 사용자의 원본 파일도 그대로입니다.
- 완전 삭제는 여전히 사용자만 할 수 있습니다. 에이전트에게 열려 있는 My DB 도구에는 휴지통 비우기도, 자동 비우기 설정도 없습니다.
- 기존 작업 폴더, 대화, 캘린더, My DB 데이터는 그대로 유지됩니다. 저장 형식 변경은 없습니다.
- v1.1.0에서 그대로 업데이트할 수 있습니다.

## 검증

- 휴지통 비우기가 **휴지통 밖을 건드리지 않는 것**을 확인했습니다 — 살아 있는 코어를 함께 두고 비운 뒤에도 그 코어가 남아 있습니다.
- 보관 파일과 버전 기록까지 사라지는 것을 실제 파일 존재로 확인했습니다.
- 기한 자동 비우기가 **기한이 지난 것만** 지우는지 확인했습니다 — 30일 전 항목과 방금 버린 항목을 함께 두고 기한 7일로 돌리면 앞의 것만 사라집니다.
- 두 판정을 돌연변이로 검증했습니다 — 기한 필터를 없애면 '기한이 지난 것만 지운다'가, 기한 `0`을 즉시 삭제로 바꾸면 '0은 자동 비우기를 하지 않는다'가 각각 실패합니다.
- 실행 중인 앱에서 전 과정을 확인했습니다 — 버림 → 남은 기한 표시 → 확인창 → 전부 삭제 → 휴지통과 DB 양쪽에서 제거 → 버튼 재비활성.
