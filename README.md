## Aiso는 무엇인가

Aiso는 **개인 창작자의 작업을 정리해주는 데스크톱 워크스페이스**입니다. 사용자가 설치한 Ollama를 기본 AI 엔진으로 사용합니다.

범용 자동 코딩 도구를 목표로 하지 않습니다. Aiso의 역할은 다음 네 흐름을 끊기지 않게 잇는 것입니다.

1. **이해** — 작업 폴더, 첨부 파일, 문서, 캘린더, My DB를 필요한 범위에서 읽습니다.
2. **정리** — 원문 근거를 가진 일정 후보를 만들고, 개인 파일을 코어 중심의 지식 라이브러리로 관리합니다.
3. **실행** — 사용자가 허용한 도구와 권한 범위 안에서 파일, 코드, 웹, Discord, 이미지 생성을 수행합니다.
4. **검증** — 결과를 다시 읽거나 명령·브라우저 상호작용으로 확인하고, 성공하지 않은 일을 성공했다고 표시하지 않습니다.

로컬 모델의 한계를 숨기지 않습니다. Aiso는 명확한 요청에 필요한 도구만 좁혀 제공하고, 복합 작업은 단계별 도구 호출·근거·결과 카드로 분리해 GPT-OSS·Gemma 계열 같은 로컬 모델에서도 예측 가능한 동작을 목표로 합니다.

## 한눈에 보는 구성

| 영역 | 하는 일 | 데이터 경계 |
|---|---|---|
| **Aiso 채팅** | 일반 대화, 첨부 자료 질의, 선택적 웹 조사 | 대화 기록은 앱 데이터, 첨부는 별도 임시 보관소 |
| **Aiso 에이전트** | 작업 폴더 기반 파일·문서·코드 작업과 검증 | 명시한 작업 폴더와 허용된 도구 범위만 사용 |
| **캘린더** | 일정 생성·수정·반복 일정·우선순위·일/주/월 보기 | 앱의 중앙 캘린더 DB에 저장 |
| **My DB** | 개인 NAS형 파일 라이브러리, 코어·파일 관계 그래프, 이력 | 에이전트 작업 폴더와 분리된 사용자 저장소 |
| **ComfyUI** | 로컬 이미지 생성, 모델 프로필과 워크플로 관리 | 사용자가 연결한 로컬 ComfyUI만 사용 |
| **Discord** | 서버 탐색, 메시지 발신, 예약·채널 보고 | 사용자가 연결하고 허용한 서버 범위만 사용 |
| **진단 센터** | 백엔드, 모델, ComfyUI, Discord, 작업 환경 상태 점검 | 읽기 중심의 상태 진단 |

## 핵심 기능

### 1. 채팅과 에이전트, 프로젝트

- 좌측 상단에서 **Aiso 채팅**과 **Aiso 에이전트**를 전환합니다.
- 채팅은 프로젝트에 묶이지 않은 일반 대화에도 적합합니다.
- 에이전트는 프로젝트별 대화방 또는 독립 대화방에서 사용할 수 있습니다.
- 대화·프로젝트는 사이드바에서 이름 변경, 고정, 삭제할 수 있습니다.
- 에이전트 실행 중에는 현재 작업 폴더, RAG 상태, 실행된 도구와 결과가 대화 흐름에 표시됩니다.

### 2. 요청별 도구 라우팅

일반 요청에 모든 도구를 한꺼번에 노출하지 않습니다. 요청 원문만 바탕으로 우선 의도를 분류하고, 필요한 도구군과 단계를 제한합니다.

| 요청 예시 | 실행 범위 |
|---|---|
| `현재 작업 폴더의 파일 구조 보여줘` | 파일 트리 조회만 |
| `기말.pdf를 읽고 요약해줘` | 해당 문서 읽기만 |
| `기말.pdf에서 해야 할 일을 캘린더에 저장해줘` | 문서 분석 → 일정 저장 |
| `현재 일정 보여줘` | 중앙 캘린더 조회, 작업 폴더 불필요 |
| `오늘 기준 최신 OpenAI 뉴스 조사해줘` | 웹 검색 → 출처 본문 확인 |
| `검색해서 특징을 파악한 뒤 그림으로 만들어줘` | 웹 조사 → 근거 확인 → 이미지 생성 |

명시적 이미지 생성은 ComfyUI 준비 상태와 선택한 모델 프로필을 확인합니다. 문서 원문이나 첨부 내용이 사용자의 실제 요청 분류를 오염시키지 않도록, 라우팅은 원본 사용자 입력을 기준으로 합니다.

### 3. 문서 읽기, 근거 중심 정리, 캘린더

Aiso는 PDF뿐 아니라 다양한 작업 문서를 읽어 요약하거나, 실제 근거가 있는 작업 후보를 추출할 수 있습니다.

- 지원 대상: PDF, PPTX/PPTM, DOCX, XLSX/XLSM, HWP/HWPX, Markdown 및 일반 텍스트
- 문서 요약과 캘린더 등록을 구분합니다. 요약 요청만으로 일정 DB를 변경하지 않습니다.
- 캘린더 생성 항목은 원문 파일·페이지/슬라이드·인용 근거를 기록합니다.
- 원문 확인은 해당 생성 시점의 에이전트 대화에서 연결해 확인할 수 있습니다.
- 모호한 문구나 문서의 서술을 억지로 마감 일정으로 만들지 않고, 실제 행동·기한·우선순위가 있는 항목을 우선합니다.

#### 캘린더

- 오늘, 일간, 주간, 월간, 연간, 목록 보기
- 시간 단위 일정과 기간 일정, 드래그 이동 및 양끝 조절
- P1/P2 우선순위와 마감 임박·오늘 해야 할 일 요약
- 우클릭으로 기한·이름·우선순위 변경 또는 삭제
- 매일·매주·매월·매년 반복 일정 해석 및 등록
- 전체 일정 삭제는 명확한 전체 범위 표현에서만 실행합니다.
- 캘린더는 작업 폴더가 없어도 앱 중앙 DB에서 동작합니다.

### 4. My DB — 개인 NAS형 지식 라이브러리

My DB는 에이전트가 만든 파일을 자동으로 쌓아 두는 장소가 아닙니다. 사용자가 직접 넣고 연결하는 **독립적인 개인 파일 저장소와 관계형 지식 그래프**입니다.

#### 저장 방식

- 파일이나 폴더를 드래그 앤 드롭하거나 `+ 파일 추가`로 가져옵니다.
- 가져온 항목은 선택한 **My DB 저장소** 아래에 관리 복사본으로 저장됩니다.
- 코어는 폴더·주제·프로젝트 단위의 상위 구조이고, 파일은 코어에 연결된 데이터입니다.
- 파일명과 코어 경로는 사람이 탐색하기 쉬운 구조로 보존합니다.
- 외부 원본 경로를 추적하는 항목은 **외부 원본 → My DB 복사본**의 단방향 동기화를 사용할 수 있습니다.
- My DB 내부 데이터는 에이전트가 임의로 삭제하거나 수정하지 않습니다.

#### 그래프와 목록

- 그래프/목록/히스토리 화면을 전환합니다.
- 빈 공간 우클릭으로 코어 생성과 방사형 검색을 사용합니다.
- 노드 우클릭으로 이름 변경, 연결, 연결 해제, 휴지통 이동을 수행합니다.
- 중간 코어를 선택하면 그 코어를 최상위로 한 포커스 보기로 전환됩니다. `Esc` 또는 마우스 뒤로가기로 전체 보기로 돌아갑니다.
- 포커스한 코어는 폴더 형태로 내보내고, 하위 코어와 파일을 선택한 위치로 복사할 수 있습니다.
- 목록에서는 코어 계층을 접고 펼치며, 파일 형식별 필터와 검색을 사용할 수 있습니다.

#### 이력과 복구

- 코어·파일·관계의 생성, 이름 변경, 삭제/복원, 파일 변경을 이력으로 기록합니다.
- 파일이 수정되면 변경점과 이전 리비전을 남겨 비교·복구할 수 있습니다.
- 그래프 체크포인트로 특정 시점의 관계 구조를 되돌릴 수 있습니다.
- 컴퓨터가 켜져 있으면 전날 변경 사항을 하루 한 번 보고서로 작성합니다. 이미 작성한 날짜의 보고서는 중복 생성하지 않습니다.
- 보고서 검사 주기는 DB 설정에서 정하며, 기본값은 6시간입니다.

### 5. 로컬 ComfyUI 이미지 생성

- ComfyUI URL과 모델 폴더를 연결해 로컬 이미지 생성을 실행합니다.
- 설치된 모델을 검사해 SD 1.5, SDXL, FLUX 계열 및 사용자 워크플로 프로필을 관리합니다.
- SDXL 자동 워크플로에는 기본 생성과 지원되는 고품질 보정 모드를 제공합니다.
- 모델이 도구 호출을 누락해도, 명확한 이미지 요청이고 준비 조건이 모두 충족된 경우에만 제한된 재시도를 수행합니다.
- 실제 `image_result`가 도착한 경우에만 이미지 생성 완료 카드가 대화에 남습니다. 생성하지 않은 이미지를 생성했다고 말하는 후속 대화 오염을 막습니다.
- 검색 기반 캐릭터 생성은 웹 조사 근거를 확인한 뒤 이미지 생성 단계로 넘어갑니다.

### 6. 웹 조사와 Discord

#### 웹 조사

- `최신`, `오늘 기준`, `조사`, `출처`가 필요한 요청은 검색 결과만 나열하지 않고, 필요한 원문을 추가로 읽어 정리합니다.
- 웹 주소, 응답 크기, 사설망 접근을 제한해 작업 폴더·로컬 네트워크를 외부 요청 경로로 사용하지 않습니다.
- 정적 설명 요청은 불필요한 웹 호출 없이 대화로 처리할 수 있습니다.

#### Discord

- 서버·채널 구조 조회, 메시지 발신, 예약 브리핑, 채널 대화 보고를 지원합니다.
- 채널 보고는 이전 보고 이후의 새 메시지만 수집하도록 커서를 유지합니다.
- Discord에서 받은 첨부 파일도 허용된 형식이면 분석 흐름에 넣을 수 있습니다.
- 최신 정보 요청은 웹 조사 흐름을 거쳐 출처와 함께 채널에 게시할 수 있습니다.

### 7. 작업 폴더, RAG, 코드와 웹 검증

- 작업 폴더는 에이전트가 파일을 읽거나 수정할 수 있는 명시적 경계입니다.
- 대용량 작업 폴더를 위한 로컬 RAG 색인과 검색 문맥을 사용할 수 있습니다.
- 파일·코드 변경 후에는 읽기, 명령 실행, Edge/Playwright 기반 브라우저 상호작용 검증을 단계적으로 수행할 수 있습니다.
- HTML 검증은 요청된 파일과 의존 변경 범위를 계약으로 추적해, 필요한 변경 전 실행되거나 엉뚱한 파일을 검증하는 일을 차단합니다.

## 안전과 데이터 경계

### 권한 모드

| 모드 | 동작 |
|---|---|
| **수동** | 영향이 큰 도구 실행 전에 확인을 요청합니다. |
| **읽기** | 조회 중심으로 동작하며 변경 도구를 제한합니다. |
| **자동** | 활성화되고 허가된 에이전트 도구를 추가 승인 카드 없이 실행합니다. |

자동은 “승인 없이 실행”을 의미하지만, 도구가 작업 폴더 밖으로 나가거나 비활성/미허가 도구를 실행할 수 있다는 뜻은 아닙니다.

### 기본 보호 장치

- 작업 폴더 상대 경로 검증과 심볼릭 링크/상위 경로 우회 방지
- 명시한 보존 파일과 디렉터리에 대한 변경 전 차단
- 도구 인자 JSON의 엄격한 검증 및 잘못된 호출의 실행 전 차단
- 도구 결과의 모델 문맥 길이 제한 — UI 카드의 전체 결과와 모델에 다시 주는 요약을 분리
- 웹 요청의 SSRF·로컬 네트워크·과도한 응답 차단
- 반복 도구 호출과 무진행 루프에 대한 단계별 제한
- NVIDIA 권한 범위, 도구 결과 재사용, 취소·재시도 시 정확히 한 번 실행되는 ledger 계약
- My DB의 개인 저장소와 에이전트 작업 폴더·대화 첨부 저장소 분리

## 진단 센터와 설정

설정의 첫 화면인 진단 센터는 실제 연결 상태를 한곳에 모아 보여 줍니다.

- Aiso 백엔드와 Python 런타임
- Ollama/NVIDIA 모델 연결 및 도구 호출·스트리밍 기능 검사
- ComfyUI 서버, 모델, 워크플로 준비 상태
- Discord 연결과 권한 상태
- 작업 폴더, RAG, My DB 저장소, 일일 이력 보고 설정
- 시나리오 기반 QA 평가팩 실행

진단은 화면을 열었다고 무제한 반복 실행하지 않습니다. 사용자가 새로 고치거나 필요한 설정을 바꿨을 때만 다시 확인하도록 설계되어 있습니다.

## 시작하기

### 시스템 요구 사항

- Windows 10 또는 Windows 11, 64비트
- 로컬 모델을 사용할 경우 [Ollama](https://ollama.com/)와 호환 모델
- 이미지 생성을 사용할 경우 별도 설치·실행한 ComfyUI
- 선택 기능: NVIDIA 계정/런타임, Discord 봇 토큰 및 서버 권한

### 설치본 실행

1. GitHub Releases에서 `Aiso-1.0.0-Setup.exe`를 내려받아 설치합니다.
2. Aiso를 열고 **설정 → 진단 센터**에서 백엔드와 모델 상태를 확인합니다.
3. 로컬 모델을 사용할 경우 Ollama를 실행하고 사용할 모델을 선택합니다.
4. 파일 작업이 필요하면 에이전트 화면에서 작업 폴더를 지정합니다.
5. 캘린더와 My DB는 작업 폴더를 지정하지 않아도 독립적으로 사용할 수 있습니다.

### 업데이트

Aiso의 자동 업데이트는 GitHub Release의 다음 파일 구성을 사용합니다.

```text
Aiso-x.y.z-Setup.exe
Aiso-x.y.z-Setup.exe.blockmap
latest.yml
```

업데이트는 현재 설치 버전보다 높은 **표준 SemVer 버전**이 필요합니다. 같은 버전의 설치본을 다시 올려도 업데이트로 감지되지 않습니다.

## 개발

### 저장소 준비

```powershell
git clone https://github.com/devbin-lab/AISO.git
cd AISO
npm ci
```

Python 백엔드의 의존성은 `python/requirements.txt`를 따릅니다. 개발 환경에서는 Python 가상환경을 준비한 뒤 해당 요구 사항을 설치하세요.

### 개발 실행

```powershell
npm run dev
```

### 품질 검사

```powershell
# TypeScript main/renderer 검사
npm run typecheck

# 렌더러 및 Node 테스트
npm run test

# Python 전체 테스트
python\.venv\Scripts\python.exe -m pytest python\tests -q

# 전체 검사
npm run test:all
```

### 아이콘 생성

앱 아이콘은 투명 배경의 NAS 마크를 여러 Windows 해상도(16–256px) ICO로 생성합니다. 문서 로고도 같은 PNG로 함께 갱신됩니다.

```powershell
npm run build:icon
```

원본은 `build/icon.svg`, 생성 결과는 `build/icon.png`, `build/icon.ico`, `docs/logo.png`입니다.

### Windows 배포본 생성

```powershell
# Python 런타임을 이미 준비한 경우
npm run build:win

# Python 런타임을 포함해 배포할 경우
npm run dist:win
```

생성물은 `dist/`에 위치합니다. 릴리스 전에는 버전, 설치 파일, blockmap, `latest.yml`이 서로 같은 버전을 가리키는지 확인하세요.

## 프로젝트 구조

```text
AISO/
├─ src/
│  ├─ main/             # Electron main process, IPC, My DB 저장소
│  ├─ preload/          # 제한된 renderer API bridge
│  ├─ renderer/         # React UI, 채팅·캘린더·My DB·ComfyUI 화면
│  └─ shared/           # main/renderer 공용 계약과 타입
├─ python/              # FastAPI sidecar, agent, tool execution, document/RAG
├─ build/               # Windows 아이콘 원본과 패키징 리소스
├─ docs/                # 릴리스 노트와 README 로고
├─ scripts/             # 아이콘·Python runtime 빌드 스크립트
└─ dist/                # 로컬 패키징 산출물(배포 대상)
```

## 문제 해결

### 모델 기능 검사가 모두 미확인으로 표시됩니다

설정 → 진단 센터에서 먼저 백엔드와 모델 연결을 확인하세요. Ollama/NVIDIA 엔진은 URL, 모델명, 인증 정보, 스트리밍·도구 호출 지원이 모두 유효해야 합니다. 단순 채팅 가능 여부와 도구 호출 가능 여부는 별도로 검사됩니다.

### 문서를 읽지 못합니다

파일을 대화 입력창에 드래그 앤 드롭하거나 `+` 버튼에서 파일을 선택할 수 있습니다. 작업 폴더 안의 문서는 에이전트가 상대 경로로 직접 읽을 수도 있습니다. 첨부 문서의 텍스트 추출과 작업 폴더 문서 ToDo 저장은 서로 다른 경계이므로, 캘린더에 근거와 함께 저장하려면 해당 문서를 명시해 요청하세요.

### 이미지 생성 완료라고 말했지만 이미지 카드가 없습니다

이미지 카드는 ComfyUI의 실제 성공 이벤트가 있을 때만 표시됩니다. 카드가 없으면 생성이 완료된 것이 아니며, 진단 센터의 ComfyUI 연결·선택 프로필·워크플로 상태를 확인하세요.

### My DB가 작업 폴더와 섞이나요

아니요. My DB는 별도 저장소와 SQLite 메타데이터를 사용하는 독립 라이브러리입니다. 작업 폴더, 대화 첨부 임시 저장소, My DB 관리 복사본은 서로 다른 목적과 위치를 갖습니다.

### 업데이트가 감지되지 않습니다

새 Release가 현재 설치본보다 높은 표준 버전인지, 설치 파일과 `latest.yml`이 같은 버전을 가리키는지 확인하세요. GitHub Release에는 설치 파일뿐 아니라 `.blockmap`과 `latest.yml`도 함께 올려야 합니다.

## 제약사항

- Aiso는 Windows 데스크톱 환경을 우선 지원합니다.
- 로컬 모델 품질은 모델·VRAM·컨텍스트 길이·도구 호출 형식에 따라 달라집니다.
- PDF/PPTX 등의 추출 결과는 원본의 스캔 품질, 글꼴, 레이아웃에 영향을 받습니다.
- ComfyUI, NVIDIA, Discord, 웹 조사는 외부 서비스 또는 사용자가 별도로 운영하는 서버의 상태와 권한에 의존합니다.
- 자동 모드는 승인 절차를 생략하지만, 활성 도구와 데이터 경계·안전 정책을 우회하지 않습니다.
